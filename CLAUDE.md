# CLAUDE.md

Мультипроектный репозиторий. Здесь — только правила, общие для всех проектов.
Правила конкретного проекта читай в его папке перед работой с ним.

Приоритет читаемости над хитроумностью. Спрашивай перед архитектурными изменениями.

## Проекты

- `life_scheduler/` — трекер задач (.NET API + React). Инструкции: `life_scheduler/CLAUDE.md`.
- `e_brain/` — второй проект, пока не начат. Инструкции: `e_brain/CLAUDE.md` (пусто).

Каждый проект самодостаточен: свои `src/`, `tests/`, `docs/`, solution-файл и скрипты.
Не клади код одного проекта в папку другого; общий код между проектами не шарим без явной просьбы.

## Память проекта

- `docs/sessions/` — общие для репозитория логи сессий, пишутся автоматически Stop-хуком.
  При старте новой сессии прочитай последний лог, если я попрошу «вспомнить контекст».
- Auto memory (`~/.claude/projects/.../memory/`) — курируется мной через `/memory`;
  не полагайся на неё как на источник архитектурных правил.
- Документация конкретного проекта (ADR, design-refs, заметки по API) живёт в `docs/` его папки.

## Хуки

`.claude/settings.json` содержит PostToolUse-хуки, которые после правок собирают и проверяют
типы в `life_scheduler/`. Если проект не относится к трекеру, отключай/настраивай хуки только
по явной просьбе.

## Браузерная автоматизация

- Используй `playwright-cli` для E2E-проверок, скриншотов и взаимодействия с UI.
- Всегда начинай со `snapshot`, чтобы получить ref'ы элементов. Не угадывай ref'ы.
- Для полей ввода используй `fill`, для кнопок — `click`.
- Сохраняй скриншоты с описательными именами: `screenshot --filename=schedule-created.png`.
- После завершения работы закрывай браузер: `playwright-cli close`.

## Code Intelligence

Для навигации по C#-коду предпочитай LSP-инструменты вместо Grep/Glob:
- `goToDefinition` / `findReferences` для поиска использований и определений.
- `workspaceSymbol` для поиска символов по всему проекту.
- `hover` для получения информации о типе без чтения файла.

Используй Grep/Glob только для поиска по тексту (комментарии, строки, конфиги).
После редактирования кода проверяй диагностику LSP, чтобы сразу видеть ошибки типов.

## Bash: запуск .NET-команд

- Для запуска `dotnet` и других CLI-инструментов **всегда используй полный путь** к исполняемому файлу, а не `export PATH=...`.
- **Правильно:** `& "C:\Program Files\dotnet\dotnet.exe" build --no-restore` (PowerShell) или `"/c/Program Files/dotnet/dotnet.exe" build --no-restore` (bash).
- **Неправильно:** `export PATH="$HOME/.dotnet:$PATH"; dotnet build ...`
- **Почему:** команды с `export` и `$()` в путях Claude Code считает «слишком сложными для автоматического анализа» и запрашивает подтверждение. Это ломает автономную работу.

## Соглашения репозитория

- Никакого `any` в TypeScript (во всех проектах). Предпочитай `unknown` + narrowing.
- Валидация — на границе (запросы API, внешние данные); внутренний код и гарантии фреймворка не перепроверяем.
- `dotnet` установлен в `C:\Program Files\dotnet` (SDK 10.0.404) — см. правило выше.
- Roslyn MCP поставляет плагин dotnet-claude-kit; отдельный `.mcp.json` в проекте не нужен.
