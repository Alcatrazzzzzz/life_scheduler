# Сессия 2026-11-25 22-25

Проверил второй вариант — **не помогло**, и это важный результат.

## Что тестировал

- Скачал `Phi-4-mini-instruct-Q4_K_M.gguf` (~2.4 ГБ, другой токенизатор — не Qwen).
- Переключил `LlmFunctionCaller` на встроенный chat-template модели (`StatelessExecutor.ApplyTemplate = true`), чтобы Qwen и Phi работали без ручного ChatML. Qwen после этого прогнал заново — работает.
- Запустил живой тест с полной GBNF и кириллицей:

```
LOCALAI_LLM_PATH=...Phi-4-mini... LOCALAI_USE_GRAMMAR=1
```

## Результат

Phi-4-mini с GBNF падает **точно так же**, с тем же стеком:

```
SafeLLamaSamplerChainHandle.Apply
  → DefaultSamplingPipeline.Sample
  → StatelessExecutor.InferAsync
```

То есть проблема не в Qwen и не в токенизаторе конкретной модели — это grammar-движок llama.cpp/LLamaSharp при генерации многобайтных токенов. Без грамматики Phi-4-mini работает (живой тест прошёл, ~52 с), как и Qwen.

Что сделано по итогам:
- `LlmFunctionCaller` теперь model-agnostic (встроенный chat-template), смена Qwen ↔ Phi — только путь в конфиге.
- В интеграционный тест добавлены `LOCALAI_LLM_PATH` и `LOCALAI_USE_GRAMMAR`, README обновлён.
- Phi-4-mini оставлен в `models/` как проверенная альтернатива без грамматики (папка в `.gitignore`); можно удалить, если не нужен.

## Что дальше

Второй вариант закрыт: **смена GGUF-модели GBNF не лечит**. Остаются:

1. **Оставить текущий prompt + JSON-парсинг + retry** — уже работает на Qwen и Phi, проверено live.
2. **ONNX Runtime GenAI + Guidance** — единственный реальный in-process путь к строгой грамматике с кириллицей. Нужен ONNX-модель (Qwen2.5-3B или Phi-4-mini) и прототип `LlmFunctionCaller`.
3. **Свежий native llama.cpp** — возможно, баг уже исправлен upstream, но LLamaSharp 0.30 — последняя на NuGet; подмена native DLL хрупкая.

Если хочешь, соберу прототип ONNX Runtime GenAI на Phi-4-mini/Qwen2.5 ONNX и проверю кириллицу через `SetGuidance` — это следующий осмысленный шаг.
