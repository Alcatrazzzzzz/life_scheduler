## Что сделано

**Модель**
- `ScheduleKind`: `Event` / `Task` / `Habit` (`Shared/Data/ScheduleEntry.cs`). `Task` — разовая и отмечаемая, `Habit` — только повторяющаяся, отметки по дням.
- `CompletedAt` на записи для задач; новая сущность `ScheduleOccurrenceCompletion` (уникальный индекс `entry + date`) для дней привычек.
- Миграция `20261120185939_AddScheduleCompletion` создана и применена к dev-БД.

**API**
- `Features/Completion/`: `POST` / `DELETE /api/schedules/{id}/completion` с проверкой типа, даты и вхождения серии. Отметка идемпотентна и обратима.
- `ListSchedule` отдаёт только `Active` и не разворачивает уже отмеченные дни привычек.
- `PastEntryArchiver`: события уходят в историю после окончания, задачи — только после конца дня, привычки не архивируются.
- `ListHistory` объединяет архивные события/задачи с отметками привычек и отдаёт `kind` + `result` (`completed` / `missed`).

**Фронтенд**
- Селектор типа в создании; для задачи скрыто повторение, для привычки обязательное.
- В деталях — тип, статус и кнопка «Отметить выполненной» / «Снять отметку».
- История показывает бейджи «Выполнено» / «Не выполнена».

## На что обратить внимание

- Календарь теперь показывает только актуальные записи: прошедшие события, как и выполненные задачи, видны только в истории. Раньше архивные записи попадали и в сетку.
- Для привычек в историю попадают только отмеченные дни. Пропущенные дни не материализуются — их можно вычислить из серии и отметок при построении отчётности. Если нужно видеть их в истории сразу, скажи — добавлю материализацию пропусков.
