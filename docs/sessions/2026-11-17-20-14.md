# Сессия 2026-11-17 20-14

Готово. Линия текущего времени теперь обновляется сама и плавно переползает к следующей минуте вместо мгновенного скачка.

**Что изменилось**

`src/Web/src/features/schedule/components/WeekView.tsx`
- Тик выровнен по границе минуты (раньше `setInterval` стартовал в случайную секунду, поэтому подпись времени могла отставать до 59 с).
- Позиция считается через `transform: translateY(...)` вместо `top` — `top` нельзя анимировать по правилам дизайн-системы, `transform` можно.
- Цель перехода — положение на момент следующего тика, иначе линия навсегда отставала бы от реального времени ровно на минуту (проверил замером: было стабильное отставание ~0.94 px).

`src/Web/src/features/schedule/schedule.css`
- `.week-now`: `transition: transform var(--duration-minute) linear` — переход длится ровно один тик, поэтому линия движется непрерывно, как часовая стрелка, без рывка на каждой минуте.
- В `prefers-reduced-motion: reduce` переход отключён.

`src/Web/src/index.css`
- Добавил токен `--duration-minute: 60s` (в DESIGN.md такого нет — это предложение; если не нравится, можно перенести в локальные переменные `schedule.css`).

**Проверка**
- В браузере (playwright) замерил: подпись меняется на `20:08` в момент 20:08:00, `transform` ползёт с постоянной скоростью ~0.93 px/мин; линия по-прежнему занимает ровно колонку «сегодня», точка и подпись на месте; при `reduced-motion` transition = `none`.
- `npm run typecheck`, `npm run build`, `npm run lint` — проходят. Бэкенд не менялся.
- Визуально скриншот посмотреть не смог (в этой сессии изображения не отображаются) — проверял геометрию и вычисленные стили через DOM.
