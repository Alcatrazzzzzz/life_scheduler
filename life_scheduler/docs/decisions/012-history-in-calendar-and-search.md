# 012 — История в календаре и фильтры истории

**Дата:** 2026-11-23
**Статус:** принято

## Контекст

По ADR 011 календарь показывал только актуальное: прошедшие события и отмеченные дни
привычек из сетки исчезали и жили только на отдельном экране истории. Из-за этого
пропадал визуальный контекст «что было в этот день», а история отдавала последние
200 записей без какой-либо фильтрации — найти старую запись можно было только прокруткой.
Нужно вернуть прошлое в календарь и дать поиск по истории.

## Решение

История становится частью диапазонного запроса календаря, а у истории появляются
серверные фильтры.

- `GET /api/schedules?from&to` отдаёт и активные записи, и архивные, и отмеченные дни
  привычек. В ответ добавлен `Result` (`None` / `Completed` / `Missed`); без диапазона
  поведение прежнее — только активные, без разворачивания повторов.
- `GET /api/schedules/history` принимает `from`, `to`, `q`, `kind`, `result`,
  `hasAttachments`. `q` ищет по заголовку и заметкам без учёта регистра; фильтры
  применяются до лимита 200. Некорректные `kind`/`result` дают `ValidationProblem`.
- Результат записи вынесен в общий enum `Shared/Schedule/ScheduleResult`, чтобы
  срезы `Schedule` и `History` не ссылались друг на друга и отдавали одинаковый контракт.
- UI: история в календаре приглушена и помечена галочкой «Выполнено» или крестиком
  «Пропущено» (`EntryMark`); клик открывает обычную карточку записи. На экране истории —
  панель фильтров с дебаунсом текста и сохранением предыдущего списка при смене фильтров.

## Альтернативы

- **Сливать историю в календарь на клиенте** — эндпоинт истории не принимает диапазон
  и обрезан 200 записями; календарь получал бы неполные месяцы и второй запрос на каждый батч.
- **Отдельный эндпоинт календаря** — дублирует контракт списка ради флага; хватает
  расширения существующего ответа полем `Result`.
- **Поиск на клиенте по загруженной истории** — у клиента нет полного набора (лимит 200),
  поиск по старым датам был бы невозможен.
- **`LIKE` / `lower()` в SQLite** — регистронезависимы только для ASCII, поиск по
  кириллице в верхнем регистре не находил бы совпадений; фильтрация в памяти корректнее.
- **Отдавать признак `Status` вместо `Result`** — календарю нужен итог, а не место
  хранения; статус `Archived` не отличает выполненную задачу от пропущенной.
- **Флаги `completed`/`missed` вместо enum** — два булева поля допускают противоречивые
  состояния; enum делает результат однозначным.

## Последствия

- **Плюс:** один диапазонный запрос даёт полную картину дня — активное и прошедшее.
- **Плюс:** фильтры применяются до лимита, поэтому старые записи находятся независимо
  от объёма истории.
- **Плюс:** общий `ScheduleResult` не создаёт зависимость между срезами и одинаково
  сериализуется в обоих ответах.
- **Плюс:** отмеченный день привычки теперь виден в календаре — раньше он молча
  пропадал из выдачи.
- **Минус:** диапазонные ответы выросли: месячный батч теперь включает архив,
  и фоновая предзагрузка (ADR 010) тянет его на все ±месяцы.
- **Минус:** `ListSchedule` стал шире по смыслу — вернул то, что ADR 011 сознательно убрал;
  два теста на «выполненное исчезает из календаря» пришлось переписать.
- **Минус:** текстовый поиск выполняется в памяти после загрузки всех архивных строк —
  для личных объёмов это дёшево, но не масштабируется на десятки тысяч записей.
- **Минус:** лимит 200 остался: при поиске пользователь не видит, что выдача усечена,
  и нет счётчика найденного.
- **Минус:** история теперь по умолчанию видна в календаре, отдельного переключателя нет;
  если визуального шума станет много, придётся добавлять режим.

## Когда пересмотреть

- Архив вырастет до десятков тысяч строк — переносить поиск в SQL (collation `NOCASE`
  для ASCII или FTS5 для русского текста) и добавлять пагинацию истории.
- Месячные батчи станут заметно тяжелее из-за архива — вынести историю за флаг
  `includeHistory` или отдельный диапазонный эндпоинт.
- Понадобится поиск по вложениям, тегам или диапазону времени суток — расширять фильтры
  вместе с индексами, а не фильтровать в памяти.
- Появится несколько пользователей или часовые пояса — пересмотреть границы дат
  в фильтрах и календарных батчах (как в ADR 003).
- Календарь начнёт визуально перегружаться историей — вернуться к переключателю
  «Показывать историю».
