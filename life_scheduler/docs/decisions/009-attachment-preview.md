# 009 — Просмотр вложений на фронтенде

**Дата:** 2026-11-20
**Статус:** принято

## Контекст

Вложения уже хранятся и скачиваются (ADR 007), но посмотреть файл можно было только
скачав его. Нужен предпросмотр картинок, PDF и Word-документов прямо в карточке записи.
Файлы лежат в S3-совместимом хранилище (локальный диск в dev), а эндпоинт скачивания
отдаёт их с `Content-Disposition: attachment` после редиректа на хранилище. Бэкенд менять
не хочется: задача целиком про отображение, а S3-путь в dev-тестах не проверяется.

## Решение

Предпросмотр — модалка поверх карточки записи; файл забирается через существующий
эндпоинт скачивания в `Blob`, из которого создаётся object URL.

- **Картинки** — `<img>`; **PDF** — нативный iframe браузера; **DOCX** — рендер
  в HTML через `docx-preview` (ленивый `import()`, отдельный чанк). Legacy `.doc`
  и прочие типы — заглушка с кнопкой «Скачать».
- Тип определяется по расширению, MIME используется как fallback: браузер часто
  присылает пустой `type` или `application/octet-stream`.
- Загрузка blob идёт через TanStack Query с `gcTime: 0`; object URL создаётся на время
  жизни открытого предпросмотра и отзывается при смене файла/закрытии.
- Сверху — список всех файлов записи, клик переключает предпросмотр; `←`/`→` и кнопки
  листают по кругу.
- Изменения только во фронтенд-срезе `features/schedule`; API и хранилище не трогаем.

## Альтернативы

- **Подставлять URL скачивания прямо в `<img>`/`<iframe>`** — `Content-Disposition:
  attachment` заставляет PDF скачиваться вместо отображения; inline-заголовок не переопределить.
- **Отдельный бэкенд-эндпоинт с inline-disposition** — требует правок API и настройки
  response headers в presigned S3; blob решает задачу без серверных изменений.
- **`mammoth` для DOCX** — даёт семантичный HTML, но теряет вёрстку и разбиение на страницы;
  `docx-preview` ближе к тому, что пользователь увидит в Word.
- **Онлайн-просмотрщики Google/Microsoft** — нужен публичный URL файла, несовместимо
  с приватными вложениями.
- **Конвертация `.doc` через LibreOffice на сервере** — тяжёлая зависимость ради редкого
  формата; отдельный срез, если формат станет важен.
- **Кэшировать blob-ы по умолчанию** — файлы до 25 МБ быстро съедают память; при закрытии
  предпросмотра данные удаляются.

## Последствия

- **Плюс:** бэкенд не меняется; работает и с локальным хранилищем, и с S3.
- **Плюс:** PDF отдаётся нативным просмотрщиком, DOCX сохраняет страницы и оформление.
- **Плюс:** `docx-preview` грузится только при открытии DOCX отдельным чанком (~171 КБ).
- **Минус:** в боевом режиме нужен CORS на бакете для `GET` с origin приложения; иначе
  предпросмотр не загрузит файл (сама ссылка «Скачать» продолжит работать).
- **Минус:** legacy `.doc` в браузере не рендерится — только скачивание.
- **Минус:** файл целиком попадает в память браузера; рендер большого DOCX нагружает CPU,
  хотя лимит 25 МБ и `gcTime: 0` ограничивают последствия.

## Когда пересмотреть

- CORS на бакете настроить нельзя — переходить на бэкенд-эндпоинт с inline-disposition.
- Понадобится предпросмотр `.doc`, XLSX или видео — серверная конвертация/превью-срез.
- Понадобятся миниатюры в списке файлов — генерировать их на сервере, а не тянуть файлы целиком.
- Появится авторизация или несколько пользователей — проверить, что blob-запросы идут
  с нужными правами и не кэшируются между сессиями.
