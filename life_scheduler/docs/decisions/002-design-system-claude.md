# 002 — Дизайн-система по референсам claude.com

**Дата:** 2026-11-17
**Статус:** принято

## Контекст

Проект домашний, один разработчик, дизайнера и UI-кита нет. Чтобы интерфейс не
собирался из случайных цветов и отступов, в качестве эталона взяты пять скриншотов
актуального claude.com (светлая и тёмная темы) — один из передовых публичных
интерфейсов на текущий день: тёплый монохром, инверсионные кнопки, иерархия линиями
вместо теней. Значения сняты попиксельно и записаны в `docs/design-refs/DESIGN.md`.

## Решение

Принимаем эту дизайн-систему как единственный источник стилей: палитра, типографика,
радиусы, отступы и контролы берутся только из токенов `DESIGN.md` / `src/Web/src/index.css`.
Новый UI строится из примитивов (`.btn--primary/secondary/ghost/row`, поля 40 px, панели r10),
а не из новых дефолтов; отсутствующий токен сначала документируется, потом используется.

## Альтернативы

- **Готовая библиотека (MUI, Ant, shadcn/ui)** — приносит свою палитру, типографику и
  размеры; подгонка под референсы дороже, чем 300 строк собственного CSS.
- **Tailwind** — токены переезжают в классы и конфиг, появляется слой сборки, а
  единственный источник стилей размывается.
- **Стили «на месте», под каждый компонент** — интерфейс расползается, каждая новая
  страница заново решает одни и те же вопросы.
- **Только светлая тема** — система уже следует `prefers-color-scheme`, а тёмная в
  референсах измерена полнее светлой.

## Последствия

- **Плюс:** один источник правды — `DESIGN.md` + CSS-токены; новую страницу можно
  собрать без дизайнера.
- **Плюс:** контрастные пары проверены по WCAG до перевода в токены.
- **Плюс:** без UI-библиотеки компонентов — стили остаются своими CSS-токенами;
  из зависимостей только `lucide-react` для иконок (16–22 px, stroke 1.5, `currentColor`).
- **Плюс:** правила сформулированы так, что их можно выполнять автоматически
  (Claude Code сверяет токены, а не вкус).
- **Минус:** референсы — маркетинговый сайт, а не приложение. Полей, таблиц, селектов
  и состояний в них почти нет: часть значений выведена и помечена в `DESIGN.md`
  как `(выведено)` — их нужно проверять глазами при каждой правке.
- **Минус:** светлая тема измерена только на странице ошибки, остальные светлые
  компоненты — инверсия тёмных.
- **Минус:** без компонентной библиотеки каждый контрол пишется руками; анимации
  120/180/240 ms и кривые не измерены вовсе — это рекомендации.
- **Минус:** референсы устареют, как только claude.com перерисуют.

## Когда пересмотреть

- Появится собственный бренд или дизайнер — система станет вторичной.
- В UI понадобятся паттерны, которых в референсах нет и которые не выводятся из
  токенов (сложные таблицы, графики, drag-and-drop).
- Аудит доступности покажет, что выведенные значения (muted-текст, danger в тёмной
  теме) не проходят контраст.
- claude.com заметно сменит визуальный язык — снимаем новые референсы и обновляем
  `DESIGN.md`, а не обрастаем компромиссами.
