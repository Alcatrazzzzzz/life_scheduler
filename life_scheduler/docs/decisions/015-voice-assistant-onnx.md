# 015 — NLU голосового помощника на ONNX Runtime GenAI

**Дата:** 2026-11-25
**Статус:** принято

## Контекст

Голосовому помощнику нужен полностью локальный NLU, который по русской фразе возвращает
строгий вызов инструмента. Первый вариант — LLamaSharp + Qwen2.5 GGUF с GBNF — падал
в нативном сэмплере llama.cpp на любой грамматике, разрешающей кириллицу; это
воспроизвелось на Qwen2.5 и Phi-4-mini, на LLamaSharp 0.27 и 0.30, во всех режимах
`GrammarOptimization`. Prompt + парсинг JSON + retry работает, но не гарантирует JSON.
ONNX Runtime GenAI с JSON-schema guidance отработал на кириллице в прототипе.

## Решение

Для NLU используем ONNX Runtime GenAI + Phi-4-mini ONNX (CPU int4), для STT оставляем
Whisper.net. От LLamaSharp, GGUF и GBNF отказываемся.

- **Модель.** `microsoft/Phi-4-mini-instruct-onnx`, папка
  `models/phi-4-mini-onnx-cpu-int4` (~4.6 ГБ), загружается один раз при старте как
  singleton. Путь задаётся `LocalAi:OnnxModelPath`, длина последовательности —
  `LocalAi:OnnxMaxLength`.
- **Структура ответа.** `OnnxLlmFunctionCaller` строит JSON-схему конверта
  `{ name, arguments }`: `name` ограничен enum инструментов, `arguments` — объект.
  `GeneratorParams.SetGuidance("json_schema", schema)` не даёт модели вернуть
  невалидный JSON; кириллица в аргументах разрешена.
- **Семантика.** Аргументы по-прежнему разбирает и валидирует `ProcessCommand`
  (типы, даты, вхождения привычек); при смысловой ошибке — один retry, затем 422.
  `HabitNameMatcher` сравнивает в том числе слова запроса, поэтому «отметь планёрку»
  матчится на «Планёрка», даже если модель вернула фразу целиком.
- **Ограничение пути.** Guidance-токенизатор ONNX Runtime GenAI не открывает пути
  с не-ASCII символами; `OnnxLlmFunctionCaller` падает при старте с понятным
  сообщением, если путь к модели содержит кириллицу. Модель лежит в ASCII-пути repo.
- **Инфраструктура.** `ILlmFunctionCaller` остаётся границей между срезом
  `VoiceAssistant` и `Shared/LocalAi`; `LocalAiStartup` прогревает Whisper и ONNX
  до `app.Run()`. `scripts/dev.ps1` проверяет `genai_config.json` и `model.onnx.data`
  и умеет `-NoLocalAi`, `-CheckOnly`, `-NoBrowser`.

## Альтернативы

- **LLamaSharp без грамматики (prompt + парсинг + retry)** — работает и проверен live,
  но не гарантирует JSON; это запасной путь, а не строгий structured output.
- **Другая GGUF-модель с той же GBNF** — Phi-4-mini (другой токенизатор) падает
  с тем же стеком; проблема не в Qwen и не в конкретной модели.
- **Свежий native llama.cpp / ожидание фикса** — LLamaSharp 0.30 последний на NuGet,
  подмена native DLL хрупкая, сроки фикса неизвестны.
- **Ollama, LM Studio, llama-server, vLLM** — дают грамматику/JSON, но нарушают
  требование «всё в процессе, без внешних серверов».
- **ONNX Runtime GenAI + Guidance** — выбран: in-process, CPU, JSON-schema,
  кириллица работает.
- **GBNF только для имени инструмента + второй вызов без грамматики** — два инференса
  и всё равно нестрогие аргументы; дороже и сложнее.

## Последствия

- **Плюс:** JSON-конверт гарантирован схемой; кириллица в именах и заметках работает.
- **Плюс:** нет падений нативного grammar-сэмплера и нет GBNF как отдельного
  хрупкого формата; LLamaSharp/GGUF удалены.
- **Плюс:** ONNX Runtime GenAI сам применяет chat-template модели; смена ONNX-модели
  не требует ручного ChatML.
- **Плюс:** проверено live: текст и синтезированный русский WAV доходят до
  `log_habit` и отметки в БД; unit-тесты и frontend-тесты проходят.
- **Минус:** модель ~4.6 ГБ (больше Qwen GGUF ~2 ГБ), плюс Whisper ~1.5 ГБ;
  16 ГБ RAM рекомендуется, 8 ГБ может не хватить.
- **Минус:** путь к ONNX-модели обязан быть ASCII; это неочевидно и требует
  fail-fast проверки.
- **Минус:** `arguments` в схеме — свободный объект; строго ограничен только конверт,
  поля валидируются после генерации. При необходимости — `oneOf` по инструментам.
- **Минус:** качество Phi-4-mini на русском и извлечение имени привычки нужно
  проверять на большем наборе фраз; при нехватке — Qwen2.5 ONNX или дообучение промпта.
- **Минус:** новая нативная зависимость ONNX Runtime и многофайловая загрузка модели;
  смена модели требует ONNX-конверсии, а не одного GGUF-файла.
- **Минус:** GPU не настроен; инференс только CPU, задержка ~10–30 с на типичном
  домашнем CPU.
- **Минус:** загрузка 4.6 ГБ при старте увеличивает время запуска и потребление RAM;
  `dotnet watch` перезагружает модель на каждое изменение C#.

## Когда пересмотреть

- LLamaSharp/llama.cpp исправят GBNF с UTF-8 — вернуться к GGUF ради меньшего размера,
  RAM и более гибкой грамматики.
- Качество Phi-4-mini окажется недостаточным для русских команд — попробовать
  Qwen2.5-3B ONNX или другую ONNX-модель, замерив tool selection и извлечение имён.
- Понадобится строгая схема аргументов по инструментам — генерировать `oneOf`/`if-then`
  из `ToolDefinitions` и проверять поддержку в Guidance.
- Появится GPU-сценарий — подключить CUDA/DirectML-пакеты ONNX Runtime GenAI.
- ONNX Runtime GenAI научится открывать не-ASCII пути — убрать проверку и ограничение
  в README.
- Модели перестанут помещаться в RAM целевой машины — smaller Whisper и/или более
  компактная ONNX-модель.
- Понадобится несколько шагов/инструментов в одной команде — вернуться к схеме
  диалога и, возможно, к другому рантайму.
